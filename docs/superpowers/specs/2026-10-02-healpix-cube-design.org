#+title: HEALPix cube (face, y, x) layout: polygon rendering with coarsening

* Context
- Issue: [[https://github.com/earth-mover/xpublish-tiles/issues/197][#197 Support healpix double pixelization]].
- Example store: ~zeus-ai/ascat-healpix~, group ~ascat/metopb/nside512/2014~.
  Vars are ~(time, face=12, y=512, x=512)~ float32, chunks ~(24, 1, 512, 512)~ (one face per chunk).
  No CF grid mapping, no ~cell_ids~. Global attrs: ~healpix_nside=512~, ~nside=512~, ~face_ordering="standard"~.
- Layout, from the writer ([[https://github.com/myzeus/zeus-healpix][zeus-healpix]] ~_fyx_to_healpix_idx~):
  ~nested = face * nside**2 + interleave(y -> odd bits, x -> even bits)~.
  This is standard HEALPix xyf (healpy ~xyf2pix~). ~nside~ is a power of 2.
- CF status: CF-1.13 HEALPix grid mapping supports only a 1-D ~healpix_index~ with
  ~indexing_scheme~ in {nested, ring, nuniq, zuniq}. The face/xy layout was proposed in
  [[https://github.com/cf-convention/cf-conventions/issues/433#issuecomment-2385991157][cf-conventions#433]]
  and not adopted. No convention to follow.

* Goals
- Detect the Zeus cube layout and render it with the ~polygons~ style.
- Coarsen exactly to a parent HEALPix level for zoomed-out tiles.
- Do not build or use an index: no ~xdggs.decode~, no ~HealpixIndex~, no ~cell_ids~ array.

* Non-goals
- Raster style (see Future work).
- ~ring~ ordering; ~nside~ that is not a power of 2; ~face_ordering~ other than ~"standard"~.
- Coarsening for the 1-D ~Healpix~ grid.
- Coarsening for ~DiscreteData~.

* Design
** Module layout
- New ~src/xpublish_tiles/healpix.py~: numba kernels and pure cube logic. No xarray grid classes.
- ~grids.py~: thin ~HealpixCube(Healpix)~ class, detection hook, refactor of ~Healpix~.
- ~pipeline.py~: one branch for the cube load and the post-load coarsen + gather.

** healpix.py
- ~fyx_to_nested(f, y, x, level)~ and ~nested_to_fyx(ids, level)~:
  ~@numba.njit(nogil=True, cache=True)~ Morton spread/compact. x on even bits, y on odd bits.
  No library has this (healpix_geo, xdggs, cdshealpix: no; healpy: GPL-2, not a dependency).
- ~coarse_level(bbox, level, max_cells) -> int~: smallest ~k~ with
  ~Ω(bbox) / (4π / (12·4**level)) / 4**k <= max_cells~. ~max_cells = config["max_num_geometries"]~.
  Returns ~level - k~. No I/O, no ~zone_coverage~ at the fine level.

** Healpix refactor
- No ~Healpix.index~ change: the cube overrides every method that reads it
  (~__init__~, ~sel~, ~cell_corners~) and keeps its own ~grid_info~.
- Extract ~Healpix._corner_array(cell_ids, depth, ellipsoid)~ from ~cell_corners~ for reuse.
- Keep the 1-D ~Healpix.Xdim~ / ~Healpix.Ydim~ properties and its ~_iter_subset_shapes~ behaviour as they are.
- Add an explicit ~HealpixCube~ branch to ~lib._iter_subset_shapes~ (like ~Triangular~) that yields
  ~(n,)~, where ~n~ is the cell count in the loaded rectangles. Required: the 2-D fall-through
  reads ~slicers[grid.Ydim]~, and the cube's slicers are not keyed by ~x~ / ~y~.
- The bbox -> nested ids code in ~Healpix.sel~ (~zone_coverage~ with the antimeridian split,
  ~EPS~ nudge, 1-ring ~kth_neighbourhood~ dilation) moves to a shared helper with a ~depth~ argument.

** HealpixCubeIndexer(HealpixIndexer)
- A subclass, so the 8 ~isinstance(..., HealpixIndexer)~ sites accept it with no change.
- Fields: ~cell_ids~ (nested ids at ~level~), ~level~, ~face~, ~y~/~x~ (fine slices read),
  ~factor~ (~2**k~), ~ys~/~xs~ (coarse positions in the rectangle). ~indices = arange(n)~.

** HealpixCube(Healpix)
- Fields: ~face_dim~, ~Ydim~, ~Xdim~, ~grid_info = HealpixInfo(level=log2(n), indexing_scheme="nested")~.
  ~crs = DEFAULT_CRS~, ~bbox~ = global.
- In-face dims are ~Xdim = "x"~ / ~Ydim = "y"~: real array dims, same meaning as in ~FacetedGridSystem~.
- ~dims = {face_dim, Ydim, Xdim}~. ~dims~ keeps ~face~, ~y~, ~x~ out of the advertised selection dims. All consumers subtract grid dims:
  tiles extents (~tile_matrix.py~ ~extract_dimension_extents~ via ~grid.dims_for~),
  WMS dimensions (~wms/utils.py~ ~var.dims - grid.dims~), and the pipeline default selection
  of extra dims (~pipeline.py~ ~grid.dims_for~).
- ~sel(bbox)~:
  1. ~L' = coarse_level(bbox, L, max_num_geometries)~, ~k = L - L'~.
  2. ~ids~ = shared helper at depth ~L'~. No ~intersect1d~: all ids exist.
  3. Face rectangles, inline in ~select~: per face that has cells,
     ~y ∈ [min(y')·2**k, (max(y')+1)·2**k)~, same for x; and each coarse cell's position in its
     face rectangle (in coarse units). Rectangle starts are multiples of ~2**k~, so blocks align.
  4. Antimeridian mask: hairline ~zone_coverage~ at ~L'~, cached per level.
- ~cell_corners~: ~healpix_geo.nested.vertices(indexer.cell_ids, depth=indexer.level)~.
- ~build_subset_dataset~: no lon/lat coords exist; the subset carries only the data var.
  ~X~/~Y~ are synthetic names (~"longitude"~/~"latitude"~), used only for the corner coords
  that ~cell_corners~ makes. ~apply_slicers~ must not add ~X~, ~Y~ or ~cell_ids_name~ to ~pick~ for the cube.
- If ~DiscreteData~: force ~k = 0~.

** Pipeline
- One ~Patch~ per face (like ~FacetedGridSystem~): ~load_plans~ concatenates the subsets of one
  plan, and face rectangles have different shapes.
- ~apply_slicers~: for ~HealpixCube~, one orthogonal ~isel(face=f, y=ys, x=xs)~ per patch.
  Lazy; loaded by the current async path. Same chunks as a pointwise load (one chunk per face);
  up to ~2x decompressed cells, because face axes are 45° to lon/lat.
- After load (~_post_load~): if ~k > 0~, ~coarsen_mean_pad(rect, {y: 2**k, x: 2**k})~.
  Then gather coarse cells into one 1-D ~cell~ dim, in ~indexer.cell_ids~ order.
- From here the subset matches a 1-D HEALPix subset. ~fix_healpix_discontinuity~ and the
  polygon render run unchanged.
- ~get_allowed_styles~: no change (~isinstance(grid, Healpix)~ covers the subclass).

** Detection
- ~find_healpix_cube_dims(ds)~ in ~guess_grid_metadata~, next to ~find_cubed_sphere_face_dim~.
  Match when a data var has dims ~(face, y, x)~ with sizes ~(12, n, n)~, ~n~ a power of 2,
  and ~ds.attrs["healpix_nside"] == n~. Else ~None~.
- Attr present but shape mismatch: log a warning, return ~None~.
- ~face_ordering~ present and not ~"standard"~: raise ~UnsupportedGridError~.
- The integer ~face~/~y~/~x~ coord values are ignored; positions come from dims.
- Takes the whole ~xr.Dataset~ (do not pre-subset by variable).

* Testing
1. Bit kernels: round trip ~fyx -> nested -> fyx~ at levels 0, 1, 5, 9.
   ~fyx_to_nested(f, 0, 0)~ is the south-vertex cell of face ~f~ (check with ~healpix_geo.nested.vertices~).
2. Synthetic dataset ~global_healpix_cube_l5~: values of ~global_healpix_l5~ rearranged with
   ~nested_to_fyx~. Tiles with ~k = 0~ (antimeridian tiles included) must be pixel-identical to
   the same tiles from ~global_healpix_l5~. Direct image compare, not a new snapshot.
3. Coarsening: cube at ~k = 2~ equals a level-3 grid from ~groupby(id >> 4).mean()~.
   Covered by ~test_cube_coarsened_matches_parent_mean~ (no zoom-0 render snapshot). ~DiscreteData~ is not coarsened.
4. Detection: ~guess_grid_metadata(ds).grid_cls is HealpixCube~. Negative cases: attr missing,
   ~n~ not a power of 2, ~face_ordering="other"~ raises. ~CubedSphere~ detection unchanged.
5. Selection dims: the ~/tiles/~ metadata snapshot for ~global_healpix_cube_l5~ advertises no
   ~face~, ~y~ or ~x~ dimension. WMS GetCapabilities for the same dataset has no ~face~ dimension.
   A tile request with no ~face~ parameter renders all 12 faces.
6. CLAUDE.md dataset steps: ~DATASET_LOOKUP~, tile list in ~testing/tiles.py~, ~test_*_data~ in
   ~tests/test_pipeline.py~, both parametrizations in ~test_tiles_metadata.py~.
7. Manual: serve ~zeus-ai/ascat-healpix~ nside512; look at z0–z6; record z0 latency.

* Open items
- Check whether ~wvc_quality_flag~ (~flag_masks~, no ~flag_values~) is classified as ~DiscreteData~.
  If not, coarsening takes a nanmean of a bit field. This is the current 2-D behaviour too.

* Known gaps
- ~adversarial_slicers~ does not shift cube rectangles. This is exact when the in-face chunk
  equals nside, and under-estimates the minzoom cost otherwise.

* Future work
- Upstream ~nested <-> (face, x, y)~ to ~healpix-geo~ (cds-healpix-rust probably has hash
  encode/decode to ~(base cell, i, j)~; orientation not checked). Then delete the local kernels.
- Raster: with ~+proj=healpix +rot_xy=45~, each face is an exact regular axis-aligned grid
  (spike result: 11/12 faces at nside 512, error ~1e-14). Face 6 (centred on lon 180°) is cut by
  the map edge, so faces need per-face ~+lon_0~. Needs raster support in ~FacetedGridSystem~
  and per-face CRS.
- Coarsening for the 1-D ~Healpix~ grid (~id >> 2k~ group-by).
- Move the ~Xdim~ / ~Ydim~ annotations from ~GridSystem~ to ~GridSystem2D~, ~Triangular~ and
  ~FacetedGridSystem~, so ~ty~ flags generic ~grid.Xdim~ access. Needs a check of every call site.
